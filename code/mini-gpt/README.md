# Mini GPT: MG-1 and MG-2

This continuing project implements the decoder-only model in Chapters 20–21. It uses explicit tensor operations and automatic differentiation, with no packaged Transformer, pretrained model, GPU, account, or external model service. Original code is Apache-2.0. Original synthetic data, measured records and small locally trained weights are CC BY-SA 4.0. No real order operation is performed.

## Run on a clean CPU environment

Run from the book repository root. Python 3.12.10 was tested. Create and activate a separate environment so `python` and notebook kernels use the same interpreter:

```sh
python3.12 -m venv /tmp/llm-book-part-iv-venv
source /tmp/llm-book-part-iv-venv/bin/activate
python -m pip install -r code/part-iv/requirements-tested.txt
python code/mini-gpt/forward.py
python code/mini-gpt/run.py --output /tmp/mini-gpt-reproduction
python -m unittest discover -s code/mini-gpt -p 'test_*.py' -v
BOOK_PYTHON=/tmp/llm-book-part-iv-venv/bin/python pnpm test:part-iv:cpu
BOOK_PYTHON=/tmp/llm-book-part-iv-venv/bin/python pnpm notebooks:part-iv
```

`requirements.txt` pins the six direct dependencies. `requirements-tested.txt` records the complete clean tested environment, including transitive dependencies. Installation needs network access; all later calculations read only local files. The notebook runner uses this interpreter in a fresh kernel per notebook, not whichever global Jupyter kernel happens to exist. Notebook 3 trains in a temporary directory and preserves the reference records.

The default training output is `data/mini-gpt/`; use `--output` for a comparison run to preserve it. `forward.py` regenerates only the deterministic MG-1 forward record. `tokenizer.py` regenerates the deterministic tokenizer from the training records. Neither uses validation to fit the vocabulary. All small checkpoints can be regenerated by `run.py`; they are included so the saved-state evidence is inspectable without retraining. The full original run, resumed continuation, fresh-process run and generation took 4.7675 seconds in the recorded environment; timings vary and are not a performance guarantee.

## Code and evidence map

| File | Responsibility |
| --- | --- |
| `tokenizer.py` | Deterministic UTF-8 byte BPE, merge replay, strict decoding and canonical identity |
| `model.py` | Record-to-tensor interface, row LayerNorm, explicit causal heads, residual FFN block, final norm, untied output head, mean valid-target loss |
| `forward.py` | MG-1 full shape trace, selected coordinate/logit rows, independent scalar loss and analytic uniform baseline |
| `generate.py` | Greedy or temperature/top-k sampling, independent RNG, append-only IDs, EOS/budget/context stops and byte validity |
| `run.py` | Bounded Adam training, evaluation, first-minimum selection, save/restore, fresh-process repeat, source identities and full generation logs |
| `test_model.py`, `test_tokenizer.py` | Independent invariants and observable failures, including wrong boundaries, changed future/padding/batch inputs and restore identity rejection |

Shared evidence lives in `data/mini-gpt/`; the data card documents all files, corpus and tokenizer boundaries. Read `data/mini-gpt/training-run.json` for all 600 batch choices/losses, 13 curve points, measured timing/environment, checkpoint sizes/hashes and source hashes. Parameter/state digests compare tensors and primitive state in a deterministic traversal. They are distinct from serialized-file SHA-256 hashes, whose bytes also depend on file format and metadata.

## Frozen experimental choices and limits

The single pre-norm block has width 16, two width-8 heads, ReLU FFN width 64, learned absolute positions, final LayerNorm, no dropout and untied embeddings/output matrix. There are 13875 learned scalars, vocabulary size 291 and context length 64. Float64, CPU, one thread and deterministic algorithms were tested with PyTorch 2.7.0 and NumPy 2.0.2 on macOS 26.5.2 arm64. Initialization seed is 1729; batch seed 101; sampling seed 31415.

The corpus is split into 24/8 whole records before encoding. Batch size 8 samples records with replacement. Loss averages valid next-token events, including EOS, excluding targets marked -100. Evaluation scores all 521 train / 178 validation events at steps 0,50,...,600. Adam uses learning rate 0.01, betas (0.9,0.999), epsilon 1e-8, weight decay 0 and `foreach=False`. There is no scheduler. The first minimum validation loss selects step 50; all subsequent points and failures are retained.

`weights-selected.pt` and `weights-final.pt` hold model state dictionaries. `resume-step300.pt` and `resume-final.pt` add optimizer state, step, global Torch/batch RNG states, configuration and semantic data/tokenizer/config identities. Restore rejects a mismatch before applying states. Files contain local tensors and primitive containers and are loaded with `weights_only=True, map_location='cpu'`. Continuation verifies the update trajectory. The full milestone separately retains the earlier curve and globally selected weights; the best point found within a resumed slice alone is not the minimum over the original complete run. The current loop saves after a completed update and clears gradients before the next, so pending gradients are not required; changing to mid-update accumulation would change the state contract.

The original diagnostic prompts omit a space after the colon. Because this BPE merges colon-space, their encoded prefixes differ from matching training prefixes. Original unfavorable outputs remain in `generation-baseline.json`; separately versioned aligned and changed-clue probes are in `generation-probes.json`. These additions followed the initial observation and were not used for checkpoint selection. One original expected suffix is underdetermined by its prompt; its mismatch is not evidence of violating an explicit supplied update.

Generation uses the full 291-candidate model distribution, then forbids BOS/PAD for selection, optionally restricts top-k, and renormalizes. Ties use smaller ID. It encodes the prompt once and appends IDs without retokenizing or a KV cache. The 64-ID input-buffer cap includes BOS; reaching that cap stops generation rather than sliding context. EOS, output budget, context limit and invalid UTF-8 have distinct evidence fields. A replacement-character display is explicitly flagged and raw bytes are retained.

These records establish a reproducible small implementation in one stack and illustrate overfitting. Near-duplicate templates, repeatedly consulted validation and qualitative probes do not establish broad language, factual, update-following or reasoning ability. Cross-stack and GPU reproduction have not been measured. A seed alone does not guarantee bitwise equality on another system.
