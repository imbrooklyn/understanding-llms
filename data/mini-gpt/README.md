# Mini GPT data and milestone card

Version: `mini-gpt-corpus-v1`; tokenizer: `book-byte-bpe-v1`. Original synthetic teaching content: CC BY-SA 4.0. Text strings are centralized here, including the Chinese records and diagnostic prompts. Fictional travel policies and order IDs do not refer to real accounts or authorize external operations. No third-party training corpus or pretrained weight is used.

`corpus.json` contains 24 training records, 8 validation records and 4 fixed diagnostic prompts with expected suffixes and purposes. The split is by complete authored record, before tokenization/window construction. Near-duplicate templates intentionally make this a memorization/generalization lesson, not an independent language benchmark. Validation is a development set for step selection; diagnostics are qualitative probes, not a final held-out benchmark. Record order is fixed. Old/new policy examples retain 600/750; an original counterfactual diagnostic asks for a new value without providing it, so its preferred suffix is underdetermined and is not used to select a checkpoint.

`tokenizer.json` is trained on training-record text only. All 256 bytes are base tokens with identical integer IDs; BOS=256, EOS=257, PAD=258. Thirty-two merges allocate IDs 259–290, for a vocabulary size of 291. Count adjacent current token pairs within each record, choose maximum count then smallest integer pair, and replace non-overlapping occurrences left to right. No normalization or pretokenization, no cross-record or special-token merges. Encode by replaying ranks; decode ordinary token payloads by concatenating bytes then using strict UTF-8. Valid Unicode input round-trips exactly. Arbitrary generated bytes may be invalid; a display using replacement decoding must identify it.

The canonical identity hashes UTF-8 JSON serialized with sorted keys, no insignificant whitespace, `ensure_ascii=False`, and separators `(',', ':')`. The tokenizer's `training_records_sha256` hashes the ordered list of training strings using this rule; the tokenizer identity hashes the complete tokenizer object. These semantic identities differ from raw-file SHA-256 values used in the validation manifest. Tokenizer identity: `9bb146ce375bda3aa518a48a60d9f69611b8d0afde9df9a8298eae9dfa9dd354`.

Regenerate the tokenizer with `python code/mini-gpt/tokenizer.py`. Complete source data and all 32 merge ranks/counts are stored, so generation needs no external model service. Forward/training records, local checkpoint provenance, versions, runtime and verification results below were produced by the actual milestone run.

## Actual milestone artifacts

- `config.json`: the complete `mini-gpt-v1` architecture, training and sampling contract. Float64 CPU, one thread, seeds 1729/101/31415, 600 updates, and selection by the first lowest full validation loss among steps 0,50,...,600.
- `forward.json`: measured MG-1 inputs/shifted targets, 32 scored events, every module shape, selected representation and vocabulary-logit rows, parameter count and scalar/analytic loss checks. Displayed chapter numbers are rounded; the JSON retains full floating-point values.
- `training-run.json`: actual MG-2 environment, 600 selected batches and pre-update batch losses, all 13 post-update complete-split measurements, timing, selected step, continuation/fresh-process results, state digests, raw source hashes and checkpoint byte counts/hashes. Loss uses natural logarithms, in nats per valid target; 521 training and 178 validation events include EOS and exclude padding.
- `weights-selected.pt`, `weights-final.pt`: locally trained model-only state dictionaries for steps 50 and 600. License: CC BY-SA 4.0, generated exclusively from the original synthetic data.
- `resume-step300.pt`, `resume-final.pt`: locally generated parameters, optimizer/RNG/step/configuration and identity state. Same provenance and license. Four checkpoint files total 966540 bytes; regenerate with `python code/mini-gpt/run.py --output /tmp/mini-gpt-reproduction` and compare semantic state rather than assuming serialization bytes are portable.
- `generation-baseline.json`: all original greedy and two original-prompt sampling runs for both selected and final snapshots, including unhelpful continuations and immediate EOS. Nothing was removed after inspecting results.
- `generation-probes.json`: separately versioned additions motivated by the original colon/colon-space token-boundary mismatch. These include aligned familiar prompts and explicit changed-color/value prompts; they were not used for checkpoint selection. The original reversed-limit diagnostic supplies no new value, so its expected suffix is underdetermined and cannot establish an explicit-update violation.
- `generation.json`: original greedy probes plus all added greedy probes and two aligned-red sampling settings for each snapshot. Every step stores its input IDs, chosen ID, raw model and selection probabilities, logits/top candidates, bytes and stop information. Generated spelling is not corrected.
