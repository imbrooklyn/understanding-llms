## Executable interface checks

The tested project pins NumPy 2.0.2 and PyTorch 2.7.0. Versioned documentation is intentionally used instead of treating the latest release as the practice environment. The live saving/loading tutorial currently identifies itself as 2.14.0+cu130; only general state-dictionary guidance is used from it, with actual loading behavior cross-checked against the 2.7 API and local tests.

## Author-derived claims and evidence routes

- Ch. 15: exact integer projection/dot-product matrices and symbolic exponential row ratios precede vectorized NumPy comparison. Changing V while holding Q/K fixed is an algebraic counterexample to interpreting an attention heatmap as the whole computation.
- Ch. 16: causal/padding truth tables are authored relations. A supplied future-copy oracle is deliberately invalid for causal evaluation; its low loss demonstrates leakage under the declared rules, not a learned benchmark. Real prefix invariance and wrong-mask tests provide separate implementation evidence.
- Ch. 17: authored two-coordinate normalization/FFN values are computed independently with scalar arithmetic. Permutation equivariance requires permuting the visibility relation too; adding positions or holding a causal triangle fixed changes that premise.
- Ch. 18: the same-key input/target records and task-selection exercise are teaching constructions. Feasible architecture choices do not establish relative model quality.
- Ch. 19: tie rules, ID order, byte coverage, normalization counterexamples, and the record boundary policy are project specifications. Exact round-trip tests establish only this encoder/decoder contract.
- Ch. 20–21: all forward values, curves, elapsed times, checkpoint comparisons, and generated strings must come from recorded actual runs. Analytic uniform-logit loss and independent attention paths are checks, not measured language skill. Repeated validation inspection is development; the tiny split is no independent benchmark of generalization.
