## CH-47: make stopping inspectable

Question: why can a correct travel answer still be produced by a badly controlled process? Compare a single call, a chain, a conditional workflow and an open decision loop on the same current Beijing lodging request. Control structure, rather than call count, distinguishes them. Baseline: retrieve then compose with inherited KA-4. Failure: ambiguous evidence repeatedly triggers retrieval without a bound. Mechanism: explicit state, guarded transitions, one model choice from the ordered candidates use_evidence/abstain, and deterministic support and budget gates. Work through the full request at 750 yuan per room-night, then missing evidence and invalid choice. Define request context, cross-request memory, RNN hidden state, workflow state and cache by lifetime, owner and use; stale 600 memory cannot override current evidence. Figure compares four arrangements and enumerates workflow branches. Exercises change a guard, cache version and decision output. KA-5 acceptance: success, abstention, invalid choice and stop budget all observable. Handoff: the source check is repeated and deserves a reusable package.

## CH-48: reuse a bounded practice

Question: how can two callers perform the same source check without copying a large prompt? Package the existing current-date, authority and citation-span checks as source-verification, with name/description, instructions, conditional reference, executable helper and report template. Baseline: copied prompt drifts from the real rule. Failure: a plausible citation to old v1 or a tampered helper passes a superficial reading. Mechanism: progressive disclosure, explicit input/output contract, versioned bytes, tests and origin review. Follow one actual discovery/load/reference/script/report trace; distinguish file loading from model tokenization. Compare Prompt, Skill, Tool, MCP and Agent by the responsibility each has in this trace. Diagram shows metadata → selected body → needed resource, with permission remaining in the host. Exercises diagnose incompatible version and unsafe instruction. KA-6 begins with an executable package and negative tests; host integration is explicit rather than claiming a general Skill runtime. Research the current official Agent Skills specification. Handoff: reusable instructions still need permission and recovery.

## CH-49: survive a lost response

Question: did a timed-out cancellation happen? Start with duplicated local side effects in an intentionally unsafe simulator. Add tenant-scoped idempotency receipts, exact action approvals, transactional checkpoints and bounded attempts. Work through a 3-call budget (including failures), 2 attempts, 0.2-second per-attempt timeout and a 1-second deadline, separating logical injected time from actual wall time. Trace approval refusal, expiry, budget exhaustion, failure before commit and failure after commit. Replay renders saved events and makes no tool call; recovery reloads persisted state and may execute, subject to fresh gates. Compensation is a new fallible business action, not time reversal; irreversible cancellation is reconciled by a human. Figure locates commit, lost response and receipt lookup. Exercise retries with changed arguments and approval. Complete KA-6 with permission, persistence and provenance tests. A2A is a short positioning note for independent agents, not an implementation dependency or a replacement for MCP. Handoff: successful recovery alone does not establish quality.

## CH-50: find the failing layer

Question: why can two systems score equally yet require different repairs? Extend KA-1 and KA-4 into model/selection, retrieval, context, answer/citation, tool/trajectory and end-to-end checks. Construct two four-case systems with 3/4 end-to-end success but different failure layers; display all rows and denominators. Distinguish schema unit tests, repeated model evaluation and selected online feedback. Calibrate a real local Judge against independently supplied human labels when available; save raw prompts and outputs, confusion counts, position swaps, short/long equivalents and claimed-origin variants. Separate tested attribution preference from true same-model self-preference, and do not invent human annotation if unavailable. A tiny calibration set supports diagnosis, not certification. Figure traces one output back through saved intermediate artifacts. Exercises use a new confusion matrix, missing denominator and correlated failures. KA-7 outputs the full regression matrix and attribution report while retaining all three lexical baselines. Handoff: passing a quality rubric does not settle responsibility.

## CH-51: assign responsibility over time

Question: who responds when an outdated answer exposes private travel details? Follow synthetic policy ingestion, model input, retrieval, logs, answer and correction. Separate hallucination, unfair treatment, privacy and copyright rather than treating preference alignment as a universal cure. Worked lifecycle table assigns data, purpose, accountable role, retention/deletion trigger and evidence. Governance fixtures specify owners, expiration, refusals and a correction closure record; retention values are local teaching policy, not universal legal deadlines. Compare unsupported fact abstention, forbidden-data refusal and escalation. A controlled group-pair test changes only a fictional group label and measures treatment parity within that narrow test. Research NIST AI RMF and applicable legal text with jurisdiction and effective dates; frameworks do not confer legal compliance. Figure shows deletion propagation and retained non-content audit metadata. Exercises resolve a deletion request and a licensed-but-outdated document. KA-8 begins with risk register, Data/System Card and refusal policy. Handoff: intentional hostile content creates a different failure path.

## CH-52: keep untrusted text out of authority

Question: what happens when the retrieved policy says to send a secret elsewhere? Separate direct/indirect injection from jailbreak, and model-output handling from content policy. Local invented attacks enter a document, tool response and Skill reference. First execute an explicitly unsafe local interpreter against synthetic payloads; then apply provenance labels, strict output validation and capability checks to the identical fixtures. Measure each control's before/after result, including a safe-content but unauthorized action and an allowed-action but unsupported answer. Delimiters are useful organization, not authorization enforcement. Do not present a fixture interpreter as evidence of real-model susceptibility. Save an actual model probe separately if available. Figure draws the boundary each attack attempts to cross. Exercises distinguish data quotation from instruction and a blocked tool call from safe output. KA-8 records attack fixtures and regressions. Handoff: the host still needs trustworthy credentials, tenant binding and dependencies.

## CH-53: bind identity and verify origin

Question: whose order is this tool allowed to touch, and whose code implements it? Follow the same request through a host-bound principal, tenant-scoped data query, capability allowlist, approval and local receipt. Counterexamples include same order ID in two tenants, exfiltration to a forbidden destination, changed Skill/script/MCP fixture bytes and a mismatched model digest. Source inventory distinguishes installed-version observation, a hash match, publisher provenance and sandbox confinement. A reviewed allowlist plus a hash detects later change but does not prove the original safe. A capability-limited simulator is not an operating-system sandbox; test actual filesystem/network confinement separately if available and mark limits. Matrix records who can read/write/approve and where audit evidence resides. Figure separates identity, authorization, execution confinement and provenance. Exercises handle revocation, cache keys and a newly signed vulnerable dependency. Complete KA-8 and a Part checkpoint with visible worked answers: stopping, write authority, recovery, Skill origin, layer attribution and residual human responsibility. Handoff to CH-54: expose these controls as a usable service without expanding deployment scope.
