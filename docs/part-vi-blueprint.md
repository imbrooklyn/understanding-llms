## Starting evidence and scope

This blueprint precedes Part VI source research, manuscript writing and new experimental execution. Chapters 34–39 are placeholders in both languages. The complete accepted Part I, master-plan sections 2–10, contributor/implementation rules, configuration, current prerequisites and adjacent Chapter 40 scope were read. Chapters 6–7, 18, 22–23, 29 and 32–33 and Primer-PY already supply the mathematical and CPU practice prerequisites. No additional primer or missing upstream project blocks this part. Chapter 40 remains an input-design chapter; this part must not implement its successors' RAG or tool interfaces.

Existing uncommitted Parts II–V, Mini GPT and knowledge-assistant work are retained. KA-1 has a frozen bilingual six-case answer contract, actual runs and disclosed author adjudication; KA-0 has unchanged nine-query Keyword, BoW Count and TF-IDF results. The small MG-2 model is a teaching model that fails the assistant gate. Its already inspected cases are development evidence for any new adaptation decision, not a blind generalization test. Historical validation documents describe earlier executions, not this task's results.

All twelve new manuscripts remain drafts without publication dates. Published Part I is preserved. Static figures, equations, visible solutions, normal navigation and existing draft filtering are reused. Only a bounded static budget-curve renderer is expected to extend shared infrastructure. No lesson controls, hidden answers, deployment, PDF, EPUB or repository publication is in scope.

## Assets and evidence design

`data/part-vi/` contains immutable teaching inputs, separately reasoned expectations, a bilingual content contract, implementation outputs and execution provenance. Teaching values, rule-derived values, controller replays, actual MG-2 measurements and cited paper measurements have distinct labels. Candidate order, ties, seeds, precision, tokenizer/model hashes, units, runtime boundaries and failure denominators are explicit.

`code/part-vi/` supplies dependency-light loss-mask, preference, verifier, budget-controller and low-rank exercises. Existing `code/knowledge-assistant/` receives the actual KA-1 adaptation extension; existing frozen runs and contracts are not overwritten. New versioned KA-1 adaptation resources stay with that continuing project. A conservative formatting repair is a useful first diagnostic: it can improve a literal-format score without changing whether the model used the right policy version. The exact intervention and comparison are frozen before the new run. It is not presented as an increase in reasoning capability.

Two CPU notebooks expose the numerical mechanisms and the real paired KA-1 comparison. Implementations and notebook notes are English; localized textbook strings are explicit data resources. Original text, fixtures and figures use CC BY-SA 4.0, code Apache-2.0; dependency licenses and any optional training/model conditions are recorded separately. No external model or paid service is required.

One figure per chapter explains a computation or causal path. Each has shared bilingual labels, caption, alternative text and source/license credit. Chapter 37 needs an actual static plotted curve with declared axes, data and line/marker distinctions. Other chapters reuse the existing responsive lane renderer, including neutral double parameter borders. Tables expose every decisive number without operating a notebook.

## Source questions to resolve before prose

Read the supporting methods and limitations of InstructGPT, DPO, process/outcome supervision and verifier research, DeepSeek-R1, chain-of-thought prompting, self-consistency, test-time compute, continued domain pretraining, adapters, LoRA and QLoRA. Check official chat-template documentation for serialization and special-token behavior. Record specific sections/equations, versions, dates, official links, assumptions and prohibited extrapolations in the research ledger. A model recipe is an example, not a universal definition. No performance or license claim may be inferred from a model family name.

## Acceptance plan

Each chapter is first completed and technically checked in English, then rewritten naturally in Chinese with the same argument, evidence, anchors, exercises and solutions. Review once for concepts/calculation/scope and again for nontechnical readability, including an independent Chinese read followed by equivalence checking. Automation does not replace either reading.

Checks must independently reconstruct key numbers and exercise boundary conditions: shifted mask alignment and zero scored targets; KL direction/support; preference rubric defects; verifier false positives/negatives; correlated votes, ties, checks and caps; unchanged KA-1 semantic decisions despite literal-format gains; low-rank dimensions/counts and quantization error. Notebook acceptance requires fresh kernels and actual output, not file readability. A separate runner avoids invalidating existing notebook provenance merely to add a collection.

Run the complete book `pnpm ci:build`, applicable CPU suites and fresh-kernel notebooks. Extend the actual Playwright entry to all twelve draft pages at desktop/mobile sizes, both figure themes and JavaScript-disabled contexts. Inspect generated figures and screenshots, equations, wide tables and visible solutions. Check language switching, anchors, draft isolation in production routes/search/RSS/sitemap and existing Part I regression. If shared site integration changes, build and compare the composed main-site artifact without deploying. Log actual commands, failures, repairs and unperformed optional work in `part-vi-validation.md`; do not predeclare success.
