We can calculate an attention head, restrict its information, assemble a block and specify a tokenizer. The remaining challenge is to make all those contracts hold at once. A program might return a plausible loss even when its labels are not shifted, its padding affects the denominator, or its vocabulary rows have changed meaning.

**MG-1** is the first complete neural Mini GPT milestone: raw text reaches logits and loss through a small, inspectable decoder-only model. It builds on Chapter 7's learning loop and Chapters 15–19's mechanisms. This chapter completes the forward route; Chapter 21 updates the same parameters. Core reading uses the static trace below. Running the code requires Primer-PY and a local CPU environment, not a GPU, model account or paid API.

## Freeze the task before creating tensors

The project uses `mini-gpt-corpus-v1`: 24 original training records and 8 validation records, already split by whole record. They contain the France-capital, red/blue key, fictional 600/750-yuan policy and fictional order-query patterns. Some templates are very similar; the split is a small development exercise, not an independent language benchmark. All raw records are visible in `data/mini-gpt/corpus.json`. Nothing queries a live order system.

Use Chapter 19's `book-byte-bpe-v1`, with vocabulary size 291, no normalization, BOS=256, EOS=257 and PAD=258. The tokenizer was fitted only to training records. One record occupies one context window. We never concatenate records or let a window cross the split. There are 64 slots; a record longer than the supported window raises an error instead of being silently truncated. These fixed records require at most 34 scored positions, including EOS; padding fills the unused slots.

The model has one pre-norm block, width 16, two heads of width 8, a ReLU FFN of width 64, learned absolute positions, and a final LayerNorm before an untied vocabulary head. Epsilon is 0.00001 and dropout is zero. Parameters are float64 CPU tensors. Initial matrix entries are drawn from a zero-mean normal distribution with standard deviation 0.02 using seed 1729; biases start at zero, normalization scales at one. These choices define a small teaching model, not the architecture of a commercial GPT product. The complete frozen configuration is `data/mini-gpt/config.json`.

## Shift the target once, then pad the unused slots

**Example 20.1 — Two records become a batch.** Take these two training records, retaining every space and punctuation mark:

```text
The key is red. Answer: red.
The key is blue. Answer: blue.
```

For the red record, byte BPE gives 14 ordinary tokens. Put BOS before them and EOS after them. The input x is that list without its last element; target y is the same list without its first element. Table 20.1 displays the whole resulting record. Indices are zero-based to match the code. The `␠` symbol in the piece column **displays an ordinary space**; it is not part of the raw text or an extra token.

There are 15 scored targets, not 14: ending the record is also predicted. BOS is known input and never a target; EOS is a target here and is not included as another scored input. Slots 15–63 contain PAD in x and the ignore sentinel −100 in y. That sentinel is a loss instruction, not a vocabulary ID. A separate Boolean array `valid` marks the 15 real query/key positions.

The blue record has 17 scored positions because this small tokenizer splits each blue into `blu` and `e`. Its complete real input IDs are `[256,84,265,268,32,277,274,101,261,65,276,119,262,259,274,101,46]`; its targets are `[84,265,268,32,277,274,101,261,65,276,119,262,259,274,101,46,257]`. Thus the batch has x, valid and y shapes `[2,64]`, but only 15+17=32 scored events. Averaging over 128 padded slots would change the objective.

In `batch_records`, this operation is the project's dataset interface: turn an already selected record list into aligned input, visibility and target arrays. Selecting a training mini-batch chooses complete records, not arbitrary pieces from validation. No large framework dataset object is needed to explain that contract.

## Trace the structure from IDs to vocabulary scores

```book-figure
ch-20/model-forward
```

Figure 20.1 maps each operation to its code name. Lookup turns integer IDs into floating-point coordinates. Position addition supplies slot information. The block communicates only through allowed attention paths and returns the same width. The final head maps that width to vocabulary candidates. There are two different probability axes: attention normalizes **source positions**, whereas the output distribution normalizes **vocabulary IDs**.

**Table 20.2 — The actual MG-1 shape log.** B=2, T=64, C=16, H=2, d=8, F=64, V=291.

| Trace entry / operation | Shape |
| --- | --- |
| Input IDs, valid flags, shifted targets | `[2,64]` each |
| `token_embedding` lookup | `[2,64,16]` |
| `position_embedding` rows | `[64,16]`, shared across examples |
| `block_input`, `norm1` | `[2,64,16]` each |
| `q_projection`, `k_projection`, `v_projection` | `[2,64,16]` each |
| `q_heads`, `k_heads`, `v_heads` | `[2,2,64,8]` each |
| `scores` | `[2,2,64,64]` |
| `visible` | `[2,1,64,64]`, shared across heads |
| `weights` | `[2,2,64,64]` |
| `mixtures` | `[2,2,64,8]` |
| `joined`, `attention_output`, `residual1`, `norm2` | `[2,64,16]` each |
| `ffn_linear`, `ffn_relu` | `[2,64,64]` each |
| `ffn_output`, `block_output`, `final_norm` | `[2,64,16]` each |
| `logits` | `[2,64,291]` |
| Mean loss over 32 valid targets | Scalar |

Q/K/V and output projections use matrices `[16,16]`. Splitting two heads reshapes coordinates and moves the head axis, as in Chapter 16. The scale divisor is the square root of 8, not 16 or 64. The singleton head dimension in `visible` means both heads receive the same causal/key-padding relation. Invalid queries are explicitly assigned zero attention mixtures; unused later logits do not contribute to loss.

A block returns `[B,T,C]`, so the output layer must still map C to V. Here it computes:

$$
Z=GW_{\text{LM}}+b_{\text{LM}},\qquad
[2,64,16]\ @\ [16,291]\ +\ [291]\ \longrightarrow\ [2,64,291].
$$

G denotes the final normalized representation, with shape `[B,T,C]`. W_LM's columns are candidate IDs in the frozen order. The output bias has one entry per candidate. The embedding table `[291,16]` and W_LM are separate parameters in this project, although some language models share their corresponding weights.

**Table 20.3 — Count every stored scalar parameter.** These counts exclude temporary activations and optimizer state.

| Component | Count |
| --- | ---: |
| Token table, 291 × 16 | 4656 |
| Position table, 64 × 16 | 1024 |
| Q/K/V plus output matrices, 4 × 16 × 16; no biases | 1024 |
| FFN, 16 × 64 + 64 + 64 × 16 + 16 | 2128 |
| Three LayerNorms, each 16 scales + 16 offsets | 96 |
| LM matrix and bias, 16 × 291 + 291 | 4947 |
| Total | 13875 |

This is a count derived from shapes and checked against registered parameters. It is not a full memory estimate: training also needs gradients, optimizer accumulators and intermediate arrays.

**Example 20.2 — Position 5 predicts red before seeing it.** Use the initial seeded model, before any update. In the first record, input index 5 is ID 277, `is␠`; target ID 270 is red. Allowed input indices are 0–5. The red token at index 6 and the later `Answer: red.` are both forbidden at this prediction.

The first token-embedding coordinate is 0.01821338003888261; the first position coordinate is 0.027941533876330877. Their sum is 0.04615491391521349. All sixteen coordinates of that input row participate in LayerNorm: mean 0.005044787486780672, variance 0.0007407640671898172. Normalizing just the displayed first few coordinates would be a different computation.

## Compute loss over candidates, then over valid events

At this position, the model returns 291 raw logits. Candidate 270 has logit 0.09915046290174213. The largest logit in the row is 0.20936204844775802; subtracting it from all candidates gives an exponentials sum of 236.07843517556194. Chapter 6's rule therefore gives:

$$
p_{270}=\frac{\exp(0.09915046290174213-0.20936204844775802)}{236.07843517556194}
\approx0.003793843386,\qquad
\ell=-\ln p_{270}\approx5.574375688.
$$

The 291 candidates, including all ordinary bytes/pieces and special entries, constitute the normalization denominator. BOS and PAD are never correct targets in this dataset, but their output columns still exist during loss calculation. Generation will separately forbid selecting them. Attention's six visible keys are not the six candidates in this denominator.

For the whole two-record batch, sum the 32 valid target losses and divide by 32. The observed mean is 5.670998865509144 nats per target. An independent scalar calculation from the returned logits gives 5.670998865509145. This batch mean need not equal the loss of the one red prediction, or the full training-set mean used in the next chapter.

A second check has a known answer before running the code. Set every vocabulary logit to zero. All 291 exponentials are 1, so each candidate gets probability 1/291; every valid target has loss $\ln(291)\approx5.673323267$. Changing the number of ignored padding slots must not change that mean. The implementation passes this analytic check too. Merely matching a prerecorded model loss would be a weaker check because that number might itself have come from a mistaken implementation.

## Let code verify the structure

`code/mini-gpt/model.py` implements the calculation with PyTorch tensors and automatic differentiation. It does not call `nn.Transformer`, a pretrained model loader, or a packaged attention block. Matrix products, coordinate normalization, masks, head reshaping, ReLU and residual additions are explicit. The model is small enough to inspect alongside Figure 20.1.

One additional Python idea is useful. A **class** describes how to create an object containing data and functions; `MiniGPT(cfg)` creates one such object. `self.token_embedding` is a tensor owned by that instance. Inheriting from `nn.Module` lets PyTorch collect tensors marked `nn.Parameter` and the parameters of its submodules. Calling `model(ids)` invokes its `forward` method. That call computes with existing parameters; it does not train them or fetch a model from elsewhere. The named `RowNorm`, `Block`, and `MiniGPT` classes organize the already explained arithmetic.

After environment setup in `code/part-iv/README.md`, use that environment’s Python interpreter to run the complete MG-1 verification from the book root:

```sh
python code/mini-gpt/forward.py
```

The program selects the two stated records and follows this call chain:

```python
cfg = config()
tokenizer = load(ROOT)
model = create_model(cfg)
ids, valid, targets = batch_records(records, tokenizer, cfg["context_length"])
model.eval()
with torch.no_grad():
    logits, loss, trace = model(ids, valid, targets, trace=True)
```

IDs and targets are `torch.long` integers; parameters and representations are float64 CPU arrays. `eval()` selects evaluation behavior, while `no_grad()` avoids building a gradient graph. With zero dropout and row LayerNorm, this model's arithmetic does not change between train/eval, but the separate meanings matter when extending it. The loss function receives raw logits; no extra Softmax is applied before cross-entropy.

Behavior checks in `test_model.py` alter future tokens, padding contents and batch companions and require real prefix logits to stay unchanged where the contract demands it. They test target shift and EOS, scalar attention agreement, analytic uniform loss, exact parameter count, and rejected empty or overlong input. Backward/update checks then establish that gradients reach the embeddings and block parameters. These are local implementation checks, not evidence of language competence.

## MG-1 is a functioning computation, not a trained ability

MG-1 now has a fixed raw-text dataset, tokenizer identity, complete structural diagram, shape log, numerical trace, logits, loss and CPU checks. It is the neural continuation of the earlier hand-count language-model project. Compared with Chapter 4's count table, this model shares parameter tables and transformation matrices across positions; its loss can train those parameters.

The untrained loss near the uniform baseline is unsurprising. Computing a loss tells us how the current parameters score the targets; it does not change them. Chapter 21 will run backward, update these same 13,875 parameters, save their training state, and ask what the changed outputs actually demonstrate.

## Exercises

1. For the red record in Table 20.1, how many input slots are real, how many are padding, and how many targets enter the mean? What error results from shifting y twice?
2. Explain the two different 64 axes in attention scores `[2,2,64,64]`, and why logits `[2,64,291]` have a different final axis.
3. If every logit were zero and only two valid targets remained, compute the expected mean loss. What would dividing their summed loss by 128 report instead?
4. Remove the output projection after concatenating two heads of width 8. Would the residual shape still match width 16? Why does this not prove the model is unchanged?
5. Add one new vocabulary entry while keeping width 16 and the existing untied matrices and bias policy. How many parameters must be added? What else must be versioned?
6. A program passes all shapes but its earlier logits change when a future token is replaced. Give two possible paths for the leak and state what MG-1 evidence must be rechecked.

## Reference answers

1. There are 15 real slots, 49 padding slots and 15 scored targets. EOS contributes the fifteenth event. A second shift would align each input with a target two steps ahead instead of the declared next token; compatible shapes would not fix the wrong task.
2. The first attention 64 is the receiving query position; the second is the contributing key position. Scores are separate for two examples and two heads. Logits instead give 291 candidate IDs at each of 64 output positions. One Softmax mixes sources; the other distributes probability over possible next tokens.
3. The correct mean remains $\ln(291)\approx5.673323267$. Dividing two losses by 128 would report $\ln(291)/64\approx0.088645676$, misleadingly small because 126 unscored placeholders were counted in the denominator.
4. Yes: two widths of 8 already concatenate to 16. But the learned W_O combines those coordinates before the residual. Removing it replaces that transformation with an identity map and generally changes the function despite matching shapes.
5. Add 16 embedding entries, 16 output-matrix entries and one output bias: 33 parameters. Version the ordered vocabulary, merges/special-token policy, tokenizer identity, data encoding and model/checkpoint configuration. Existing rows must retain their meanings or be deliberately migrated.
6. Attention may use an absent/reversed causal mask, or normalization/preprocessing may mix future positions before attention. Recheck visible relations, actual prefix perturbations, coordinate-only norms and target construction. A complete diagram and numerical trace should identify the permitted path; shapes alone cannot establish it.
